# A1 判别式高分辨率主表结果

日期：2026-07-23
实验：`ANALYSIS-IDEA1B-A1-DISCRIMINATIVE-001`
状态：完成

## 一句话结论

在逐图真实码率完全相同的 Kodak/CLIC 高分辨率合同下，S33 只在 Kodak 的 PSNR 上追平 official Base-SA；面对参数匹配 CM-SA，以及在更大的 CLIC test 上面对两条 SwinJSCC 臂，S33 均未通过 0.10 dB 非劣门槛，感知和结构指标总体也更差。因此本轮保守结论是：

> **S33 没有在领域惯例高分辨率 benchmark 上战胜 SwinJSCC；当前是“更低推理代价、但质量较低”的效率—质量端点，不能再写成强于 SwinJSCC 的纯 backbone。**

## 公平合同与完整性

- 三臂：S33 `31.03M`、official Base-SA `28.18M`、capacity-matched CM-SA `31.35M`。
- 每个 256×256 tile 都真实发送 `16,384 real`，三臂使用相同 tile、边界 padding 和逐图 canonical noise。
- Kodak：24图×5 SNR×3 seeds，共1080行；每图 actual CBR 恰为 `1/24`。
- CLIC2020 test：428图×5 SNR×1 seed，共6420行；因共同边界 padding，逐图 actual CBR 为 `0.041667–0.063210`，均值 `0.045472`。三臂在同一图上 actual symbols、CBR 和 noise SHA 完全相同。
- 重建和指标合计7500行，无缺失、无重复；official Imagenette validation 未访问；DiffJSCC、SGD 和 refiner 未加载。
- CLIC 只有一个 channel seed，因此其 source-cluster CI 量化图像总体不确定性，不声称跨 channel seed 稳健。

## 语义指标边界

Kodak/CLIC 没有适合本合同的分类标签，本轮预注册的是原图—重建图 OpenCLIP image cosine，而不是监督语义失败率。不能在结果后选择 CLIP 阈值，再把它包装成“语义失败”。Imagenette 的监督 reliability 仍可作为另一个封存层，但 official validation 本轮没有解封。

## 系统代价与新的方法判断

最大 2048×2048 CLIC 图、batch=1、同运行时下：

- S33：`189.7 ms`，peak reserved `1.21 GiB`；
- Base-SA：`439.5 ms`，`2.20 GiB`；
- CM-SA：`464.4 ms`，`2.21 GiB`。

所以 S33 仍有约 `2.32–2.45×` 的延迟优势和约一半显存占用，但它买来的是明显质量损失。当前合理立论不再是“S33 是更强 backbone”，而是：

1. S33 是便宜的判别式端点；
2. Swin 是更慢但更高质量的判别式端点；
3. 后续轻量 receiver-side refiner 若要成立，至少要证明它能以远低于 Swin/扩散的增量代价缩小上述质量差距，并保持等码率和可靠性。

## DiffJSCC 码率决策

现成 DiffJSCC official OpenImage C16 checkpoint 原生 actual CBR 为 `1/96`。要达到 `1/24` 必须把 `C_channel=16→64`，会改变 encoder/decoder 权重形状，不能靠推理时改配置、补零或重复潜变量得到。若不新训 C64，A2 只能做 rate–quality Pareto；若要“真·等码率 S33 vs DiffJSCC”，必须单独授权并重训 C64 及匹配生成阶段。
