# S34A SwinJSCC 等预算阶段结果（2026-07-22）

## 结论先行

S33 strong backbone 在严格相同的 `16,384 real` 码率、COCO 训练数据、12 epochs/equal-step 预算和同一 canonical AWGN policy-dev 合同下，**显著超过官方默认 Base-SA，但没有通过参数匹配 CM-SA 的 `0.10 dB` 非劣 gate**。因此本轮不能写“超过 SwinJSCC”，只能写成：

> S33 在同等训练预算下显著超过官方默认规模的 SwinJSCC；面对约 31M 参数的 capacity-matched SwinJSCC，S33 的平均 PSNR 仅低 `0.0659 dB`，且语义失败率更低，但 PSNR 非劣 CI gate 未通过，MS-SSIM/LPIPS 显著落后，形成 Pareto。

两条 SwinJSCC 臂在 epoch 9--12 都仍明显上升，所以这只是 **equal-budget 结论**，不是“各自充分收敛”结论。按用户授权，extension 没有启动；official Imagenette validation 没有访问。

## 冻结合同

- 官方源码：`semcomm/SwinJSCC@a6d0e6da53548976acbe9317839a077ef31f190f`。
- 双臂：official Base-SA `28,182,512` 参数；capacity-matched CM-SA `31,348,752` 参数；S33 为 `31,028,163` 参数。
- 码率：三者均原生发送 `64x16x16=16,384 real`，无 mask、padding 或 side information。
- 训练：相同 COCO、FP32 `4+8 epochs`、相同 optimizer-step 数、逐图离散 `[1,4,7,13,19] dB`、MSE-only checkpoint selection。
- 评估：冻结的 64 图 × 3 channel seeds × 5 SNR，共每臂 960 行；相同 16,384-D canonical noise prefix。
- 指标：floor-uint8 PSNR、MS-SSIM、LPIPS、冻结 `T_cls` failure；以 source image 为 cluster 做 10,000 次 bootstrap 95% CI。
- 判据：`S33−Swin` PSNR CI 下界 `>0` 为显著超过；在 `(-0.10,0]` 为非劣；`<-0.10` 按预注册标签为劣于/未证明非劣。二级指标冲突时只能写 Pareto。

## 工程失败与恢复记录

训练权重没有损坏，失败都发生在正式逐样本推理前，并按 fail-closed 保留：

1. 评估器最初要求 checkpoint 顶层必须有 `arm`，但训练 checkpoint 的格式只在冻结训练 summary 中保存 arm。修复后采用“summary 绑定 arm→path→SHA + checkpoint epoch/phase + expected architecture strict state-dict load”的等价且更强审计；若未来 checkpoint 提供 `arm`，仍会显式核验。
2. 第二次启动先调用 `requires_grad_(False)`，再用只统计可训练参数的函数核对参数量，导致计数为 0。修复为先核对 `28,182,512/31,348,752`，再冻结梯度。
3. 两次失败均未生成任何 per-sample CSV；最终 resume 使用未改变的 config，并在输出目录保存原脚本、两版恢复脚本及 resume event，未覆盖失败证据。

## 当前决策边界

- **现在能说的：** S33 显著超过官方默认 Base-SA；与同容量 CM-SA 接近但没有证明非劣；S33 在语义失败率上更稳，CM 在感知/结构指标上更强。
- **现在不能说的：** “S33 超过 SwinJSCC”“S33 已战胜更强 Transformer backbone”或“双方均已收敛”。
- **下一项需要用户授权的决定：** 是否为已触发 gate 的 Base-SA 和 CM-SA 启动分阶段 extension。充分训练口径没有完成前，S34A 不能冻结，S34B 消融、S35 diffusion 和 official validation 继续等待。
